## 4. docs(readme): 工作原理改为一段人话,术语交给指南

`README.md`

**提交**：`bcd0401`

**为什么改**

原文用 Host face / Client face / Bridge / WebMessage / addJavascriptInterface / 回环代理 描述三层结构，还把默认上游端口和阅读模式的开关说明塞在同一段里。读者是来确认“安全吗、要不要改我的 DSH 吗”，这些实现名词回答不了这个问题。

现在先给一句可复述的解释（手机连加密入口，入口转给 DSH），再明确“不修改 DSH 源码、可随时关闭”，细节指向 docs 目录。阅读模式的说明不属于工作原理，随本次一并移除，功能入口仍在设置页。

**原文**

```text
插件包含三层：Host face 负责发现、配对、HTTPS、回环代理和扩展注册表；Client face 提供独立的移动布局与扩展 SDK；Android App 提供受限的原生 Bridge。Bridge 使用 `androidx.webkit` WebMessage，每条消息都校验精确顶层 Origin 和主 Frame，并限制消息大小；不使用 `addJavascriptInterface`。插件不改写 DeepSeek Harness 安装目录中的源码或网页文件；移动网关按请求提供启动兼容层与专用布局，安装和卸载通过插件机制完成。DSH Web 上游端口默认为 3080，可通过 `dsh web --port` 修改。阅读模式（可选，默认关闭）：向下滚动阅读长会话时收起输入栏的编辑区，输入框卡片与发送/停止按钮保留；点按卡片、聚焦输入框、打开软键盘或向上回滚约 80px 即恢复。有草稿、提交中或回复生成中时不会收起。可在「设置 → 通用」中开启。
```

**修改后**

```text
### 它是怎么工作的

一句话：**手机不直接连你的电脑，而是先连上电脑里 DSH Mobile 开的一个加密入口，再由这个入口转给 DSH 本身**。所以手机上看到的还是同一份会话、工作区、消息和工具，不需要另装一套 DSH。

插件不改 DeepSeek Harness 的任何源码或网页文件，装和卸都走插件机制，随时可以关掉。想了解各配置专题和实现细节，见[使用指南目录](docs/README.md)。
```

**修改后**

```text
会话切换后会重建连接。如果你经常在几个会话之间来回切，可以在「设置 → 通用」里打开「预取刚离开的会话」，切回去更快；默认关闭，觉得占资源或出问题随时关掉即可。
```

## 7. docs(readme): Windows 权限失败改为“重试再交诊断报告”

`README.md`

**提交**：`f636498`

**为什么改**

原文解释日志里 sid-query / acl-apply 两个阶段名各代表什么，要求用户提供阶段、耗时、错误码和 DSH 版本，末尾还注明这不代表另一个启动争抢问题已解决。用户既读不懂阶段名，也没有采集这些字段的入口。

现在只说三件事：别关权限检查、先重试一次、还不行就用连接诊断的脱敏报告，那条报告本身就是这些字段的集合。

**原文**

```text
- **Windows 初始化停在权限处理或失败**：日志中的 `sid-query` 表示查询当前账户 SID，`acl-apply` 表示应用私有文件权限，错误同时记录该阶段的完整等待耗时。不要关闭权限检查或把敏感文件改为所有人可读；提供脱敏后的阶段、耗时、错误码和 DSH 版本以继续定位。分阶段诊断不代表 [#128](https://github.com/saya-ch/dsh-mobile/issues/128) 的启动争抢问题已经解决。
```

**修改后**

```text
- **Windows 初始化停在权限处理或失败**：这时卡在给插件自己的目录设置权限。**不要**关闭权限检查，也不要把这些文件改成所有人可读。先重试一次；仍失败就在电脑端打开**移动访问 → 连接诊断**，把生成的脱敏报告发出来，比手动翻日志快得多。
```

## 11. docs(readme): mirror the plain-language How it works in English

`README.en.md`

**提交**：`280706e`

**为什么改**

Same treatment as the Chinese section: one repeatable sentence about the encrypted entry point, an explicit "does not modify DSH", and a pointer to the documentation index. The Host face / Client face / WebMessage / loopback wording and the reading-mode paragraph leave the overview.

**原文**

```text
Three layers: the Host face for discovery, pairing, HTTPS, loopback proxying, and extension registration; the Client face for the dedicated mobile layout and extension SDK; and the Android app for a narrow native bridge. The bridge uses `androidx.webkit` WebMessage, which verifies the exact top-level origin and main frame on every bounded message, and never uses `addJavascriptInterface`. The plugin does not rewrite source or webpage files in the DeepSeek Harness installation. Its mobile gateway serves the startup compatibility layer and dedicated layout per request; installation and removal use the plugin mechanism. The upstream DSH Web port defaults to 3080 and is configurable through `dsh web --port`. Reading mode (opt-in, off by default) collapses the composer editor while scrolling down a long conversation: the card and its Send/Stop row stay, and tapping the card, focusing the composer, opening the software keyboard, or scrolling back up about 80px restores it. It never collapses while a draft exists, a submission is in flight, or a reply is streaming. Enable it from Settings → General.
```

**修改后**

